# V4-003 Exact Dungeon Combat Outcome (Victory / Defeat)

Purpose: make DungeonRuntime resolve an outcome — and only one outcome — when combat concludes, and drive the existing authoritative DungeonManager state + WaveManager result bridge. Today nothing in production calls `DungeonManager.complete_run()/fail_run()` or `WaveManager.report_dungeon_result()` (grep confirms they are dead code), so after combat the arena sits unresolved unless the player manually closes it.

Reuse: DungeonRuntime RunPhase (V4-002), `died` signals already wired (`_on_party_actor_died` erases member, `_on_enemy_died` erases enemy), `take_damage()`/`alive` on MercenaryActor3D/EnemyActor3D, `end_run()`, DungeonManager (`complete_run`, `fail_run`, `get_dungeon`), WaveManager (`report_dungeon_result`, `is_dungeon_clear_applied`, `DUNGEON_CLEARED`), DeathLedger (actor deaths already recorded by actors themselves — this task must not double-record).

Constraints: no fake/test-only resolve API in production; no new combat rules/balance changes; no UI; DungeonRuntime is NOT an autoload. The outcome query must be a real read of live actor state (`alive`/tracked arrays), reusable by the simulation.

Requirements:
1. Add `enum Outcome { NONE, VICTORY, DEFEAT }`, `get_last_outcome() -> Outcome`, `get_last_outcome_name() -> String` (NONE initial/after IDLE), and `func evaluate_outcome() -> String` returning "VICTORY"/"DEFEAT"/"" by reading alive/tracked actors:
   - enemies all dead (or `_enemy_actors` empty) and at least one alive party member → "VICTORY" (priority over DEFEAT so a same-frame mutual wipe is not ambiguous: enemies empty first wins only if a party member is still alive).
   - otherwise all party actors dead (empty living party) → "DEFEAT".
   - both empty or not all-dead → "".
2. Phase-aware resolution: only in DEPLOYMENT/COMBAT; resolution is exactly-once per run guarded so re-evaluations cannot re-emit. On VICTORY: `DungeonManager.complete_run(dungeon_id)` then `WaveManager.report_dungeon_result(WaveManager.DUNGEON_CLEARED, dungeon_id)` (exact run id = dungeon_id), then phase RESOLVED and `end_run()` cleanup (alive party returns via roster as today). On DEFEAT: `DungeonManager.fail_run(dungeon_id)` + `report_dungeon_result(WaveManager.DUNGEON_FAILED, dungeon_id)`, then RESOLVED + end_run(). Guard must make a second evaluate_outcome() on the same run return ""/no-op.
3. Add `signal run_outcome(outcome: int, dungeon_id: String)` emitted exactly once per resolved run (before end_run cleanup).
4. end_run remains idempotent; get_last_outcome() persists the last resolved outcome (button still NONE right after end_run of an unresolved manual close-down, since manual end_run has no outcome).

Validation (tests/v4003_test.gd, `extends SceneTree`, headless, `V4003_ASSERTIONS`/`V4003_RESULT` marker contract): use a fully deterministic forced-resolution sequence through real actors + public damage API (EnemyActor3D.take_damage and MercenaryActor3D.take_damage exist; call `take_damage(999)` and re-evaluate via evaluate_outcome(), not timers):
- VICTORY path: begin_run a real run, kill every enemy with take_damage(999), assert evaluate_outcome()=="VICTORY" when phase in {COMBAT,DEPLOYMENT}, dungeon state became CLEARED, completion_count incremented to 1, `run_outcome` fired exactly once, `WaveManager.is_dungeon_clear_applied("ne_ruins") == true`, and a second evaluate_outcome() returns "" (guarded).
- DEFEAT path: second real run (re-prep + `DungeonManager.mark_ready`, expected after a CLEARED), kill every party member, assert evaluate_outcome()=="DEFEAT", state FAILED, clear NOT applied for the second run id outcome (DUNGEON_FAILED must not call apply_dungeon_clear), run_outcome fired once.
- No DeathRecord double-record assertion: killing party members via take_damage records their deaths via the actor pipeline exactly once each (use DeathLedger count deltas if observable).

Exit quit(0) only after markers. Also required: `tests/baseline_3d_health_test.gd` passes.
