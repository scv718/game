# V4-001 NE Ruins Discovery → Dungeon Preparation/Entry Gating

Purpose: make the first dungeon `ne_ruins` usable in play only **after** its exploration region `ne_dungeon` is genuinely discovered. Today `DungeonPreparationManager.create_preparation()` and depart() work without any discovery check, so the dungeon loop can run before the player ever explored NE Dungeon. Wire the existing exploration data into the dungeon gate so discovery is a hard prerequisite for preparation and entry.

Reuse: ExplorationManager (autoload, region `ne_dungeon`, signal `region_discovered`), ExplorationRegion (`DiscoveryState { UNKNOWN, EXPLORING, DISCOVERED }`, `get_discovery_state()`), DungeonManager (definition `ne_ruins` has `region_id == "ne_dungeon"`; `create_dungeon()`, `has_dungeon()`), DungeonPreparationManager (`create_preparation()`, `depart()`), DungeonPreparation.

Constraints: no save system, no new UI panel, no changes to GAME_DESIGN.md, no invented "dungeon unlock items". Do not probe `root.get_node_or_null("/root/DungeonRuntime")` (DungeonRuntime is NOT an autoload). Keep the preparation/roster API surface unchanged (additive gating only).

Requirements:
1. DungeonManager exposes an authoritative lock query, e.g. `is_dungeon_unlocked(dungeon_id) -> bool`: false for unknown definitions or when the dungeon's `region_id` region is not DISCOVERED (use the real ExplorationManager region state; no copied discovery state in DungeonManager).
2. DungeonManager connects to `ExplorationManager.region_discovered` (autoload order: ExplorationManager is ready before DungeonManager) and, when the discovered region_id matches a registered definition, creates the dungeon instance once (create_dungeon) and emits a `dungeon_unlocked(dungeon_id)` signal. Purely pull-based `is_dungeon_unlocked` must stay correct even without the signal (region state is the single source of truth).
3. DungeonPreparationManager.create_preparation() returns false (no preparation created) while the dungeon is locked. Both preparation creation and depart() must refuse locked dungeons (choose the minimal, consistent gate points; the observable behavior is: no prep and no entry before discovery).
4. Discovery via the real public exploration flow (start_exploration → advance(): set_progress(region_id, 1.0) then advance(0.05)) must unlock everything, including the discovery-side instance creation and the `dungeon_unlocked` signal.

Validation (tests/v4001_test.gd, `extends SceneTree`, run headless): record each assertion, then print
`V4001_ASSERTIONS=<passed>/<total>` and `V4001_RESULT=PASS`, and `quit(0)`. On any assertion failure print `V4001_RESULT=FAIL` and `quit(1)`. Assertions must observe real autoload state, must not be vacuous (no skipped bodies), and must include at least:
- ne_ruins is locked (DungeonManager.has_dungeon("ne_ruins") == false OR is_dungeon_unlocked false) before discovery, and create_preparation("ne_ruins") returns false there (use ExplorationManager.set_auto_advance(false) so _process doesn't race).
- After real discovery of ne_dungeon (public API above), is_dungeon_unlocked("ne_ruins") becomes true, has_dungeon("ne_ruins") becomes true (DISCOVERED or later state), create_preparation returns true once and false on duplicate.
- The `dungeon_unlocked` signal fires exactly once during that discovery (connect a listener before discovery).

Also required: `tests/baseline_3d_health_test.gd` must still pass (BASELINE_3D_RESULT=PASS).
