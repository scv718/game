# V4-002 Dungeon Runtime Run Phase Machine

Purpose: replace DungeonRuntime's private boolean `_active` lifecycle with an explicit, observable run phase machine: `IDLE → DEPLOYMENT → COMBAT → RESOLVED → IDLE`. Today the arena spawn/advance happens all inside begin_run with no phase state, so callers/UI can't tell deployment (party advancing to rally) from combat. This task adds the phase state machine only; outcome detection is V4-003.

Reuse: DungeonRuntime (arena scene, spawn_party, spawn_enemies_for_dungeon, `_activate_encounter_advance`, end_run, signals `encounter_started`/`encounter_ended`), DungeonDefinition state, DungeonPreparationManager.run_started bridge.

Constraints: no physics/combat changes, no UI, no new scene, no second combat system. DungeonRuntime is NOT an autoload — do not probe /root/DungeonRuntime in tests; instantiate `load("res://scripts/dungeon_runtime.gd").new()` and add to the tree, then drive begin_run/end_run (follow the pattern of the existing V3 dungeon runtime tests). Keep all existing public API working (begin_run/end_run/is_run_active/...).

Requirements:
1. Add `enum RunPhase { IDLE, DEPLOYMENT, COMBAT, RESOLVED }` plus `get_phase() -> RunPhase` and `get_phase_name() -> String` (stable names via a const map like `DISCOVERY_STATE_NAMES`). Default phase is IDLE.
2. Add `signal phase_changed(from: int, to: int)` (or (phase)) emitted on every phase change.
3. Transitions:
   - begin_run success: IDLE → DEPLOYMENT (arena + party + enemies spawn stage), immediately after a successful `_activate_encounter_advance()` with at least one alive enemy tracked → COMBAT. COMBAT transition must happen deterministically during begin_run when enemies exist (DEPLOYMENT fire must precede COMBAT fire in signal order).
   - end_run: guard only `_active`; entering end_run from a non-IDLE phase: COMBAT (or DEPLOYMENT) → RESOLVED → then cleanup → IDLE. RESOLVED must be observable to signal listeners before IDLE; the last emitted phase before IDLE is RESOLVED even for manual end_run (no outcome). end_run while IDLE stays a no-op returning 0.
4. Invalid calls (begin_run while not IDLE, begin_run on already-active run) stay false / refused as today.

Validation (tests/v4002_test.gd, `extends SceneTree`, headless, same marker contract as V4-001 but with `V4002_ASSERTIONS` / `V4002_RESULT`): build a real prep + dungeon instance exactly like existing dungeon runtime tests (needs a dungeon IN_PROGRESS, a prep with member_ids, alive mercenaries in MercenaryRoster, and the arena scene loadable), then assert:
- fresh instance phase == IDLE.
- begin_run succeeds → phase is COMBAT (deployment completed) and the recorded phase_changed history has DEPLOYMENT strictly before COMBAT.
- end_run returns >0 and phase returns to IDLE, with RESOLVED appearing in history immediately before IDLE.
- after end_run, is_run_active() == false and get_party_count()/get_enemy_count() == 0.

Exit with quit(0) only after the marker prints. Also required: `tests/baseline_3d_health_test.gd` passes.
