=============================================================================

태스크 완료조건 "확인된 병목은 기록"의 산출물이다.
자동 회귀: tests/task3dint0022_test.gd (headless) => TASK3DINT0022_RESULT=PASS

원칙 준수: 대규모 최적화 시스템(MultiMesh/ECS/LOD 등)은 만들지 않았고,
실측으로 확정된 병목 1건만 최소 개선했다.

-----------------------------------------------------------------------------
1. 확정 병목 - 월드 전체 navmesh 동기 bake 1회 약 3.9~4.6초 (치명적)
-----------------------------------------------------------------------------

증상:
  Tree 고갈/regrow마다 request_rebuild_debounced(0.1s debounce)가 동기
  rebuild_navigation()을 깨웠고 메인 스레드가 수 초간 완전 정지했다.
  벌목이 진행되는 동안 화면이 수 초 간격으로 멈추는 사용 불가능 등급.

측정 분해 (PERF baseline.parse_split_ms):
  parse(정적 collider 수집) 4.6ms vs bake(raster) 4203ms
  => 비용의 99.9%가 raster다.

근본 원인:
  nav cell 해상도 0.125 unit(1px)에서 ±192 unit 월드 = 3072x3072 약 940만 cell.
  bake/map-sync 비용은 cell 수에 비례한다.

최소 개선 (2건):

  (1) scripts/navigation_policy_3d.gd
      NAV_CELL_SIZE_UNITS 0.125 -> 0.5 (논리 4px, PARSE_AGENT_RADIUS 8px의 절반
      그리드). cell 수 약 16배 감소.
      NAV_CELL_HEIGHT_UNITS = 0.125 는 유지했다. "표면이 지면 Y에서 cell 1개
      이내"라는 Actor Origin LOCK 하드 요건은 세로 해상도에 달려 있어 건드리지
      않았다. carve 경계 양자화 오차는 cell/2 = 0.25 unit 이내로
      agent_radius(1.0) erosion이 흡수한다.

  (2) scripts/navigation_manager_3d.gd
      런타임 churn용 rebuild_navigation_async() 추가: parse는 동기로 최신
      스냅샷, raster bake는 워커 스레드(bake_from_source_geometry_data_async),
      완료 콜백에서 region 할당. debounced flush(트리 고갈/regrow/gate/
      placement 등 모든 runtime churn)를 async 경로로 전환.
      - generation 부여: 완료 순서가 밀린 오래된 결과가 새 map을 덮어쓰지 않음.
      - 대기열 depth-1 collapse(respin): bake 진행 중 재요청은 큐에 쌓지 않고
        완료 후 최신 상태로 1회 재발행. 연속 depletion이 착지 히치를 연발하는
        것을 구조적으로 차단.
      - 동기 rebuild_navigation() 계약은 유지(테스트/초기 bake/probe 복원).
      - nav_rebuild_count는 양 경로 모두 발행 시 증가(기존 소비자 폴링 의미 불변).

개선 전후 실측 (headless CPU 기준, 동일 머신):

  항목                                        개선 전        개선 후
  ------------------------------------------------------------------
  동기 nav bake 1회 (baseline world)          3896.8ms       208.1ms
  동기 nav bake 1회 (stressed world, Tree108) 4611.0ms       291.7ms
  camera overview+zoom >150ms 스파이크        다발(최대441ms) 0건 / 420 tick
  8기 동시 navigation 스파이크                다발            0건 / 894 tick

  node/orphan/memory runaway                  없음            없음

  최종 PASS 실행 5개 샘플링 창 전부 tick_wall_avg = 16.63~16.74ms
  (60fps 케이던스 유지), >150ms 스파이크 0건.

계약 변경 요약 (후속 태스크 주의):
  - debounce flush는 eventually-consistent. 요청 -> map 반영 지연 상한은 bake
    소요 시간(현재 약 0.2~0.3s). 물리 collision은 종전대로 즉시 반영.
  - 결정적 map 신선도가 필요한 경로는 동기 rebuild_navigation()을 계속 사용.
  - nav_rebuild_count = "발행된 rebake 수". async 완료는 navigation_baked 신호로
    관측.

    physics tick 경계 사이 실측 wall time(tick_wall_avg_ms)으로 한다.
